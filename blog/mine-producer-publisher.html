X営業が嫌すぎて、AIで「営業するタヌキ」を作った

2026-10-01 · Project Tanuki

私は開発が好きである。

思いついたものをChatGPTに投げ、作って、壊して、直して、「なんでやねん」と言いながら少しずつ動くようにしていく。これは楽しい。

問題は、完成した後だった。

作ったものは、黙っていても誰にも知られない。

つまり営業が要る。

そして私は、営業があまり得意ではない。

ある日のチャットで、ついにこう言った。

ワイ

バカにしやがって、、、タヌキXを作製して投稿係に任命できないのかなぁ

ChatGPT

できる。しかも、こっちの方がタヌキ思想に合っとる。

普通ならここで「SNS運用を勉強しましょう」となるのかもしれない。

なぜか私たちは、投稿係そのものを作り始めた。

数分後にはTanuki Xを正式な投稿係として立ち上げ、その数分後には実装まで進んだ。

営業が嫌だと言っただけなのに、社員が一匹増えた。

「営業を頑張る」をやめて、工程を分けた

あとから整理すると、やったこと自体は意外と真面目だった。

SNS営業には、少なくとも次の仕事がある。

  1. 過去の出来事からネタを探す
  2. 読める文章にする
  3. 今日出すものを選ぶ
  4. 実際に投稿する
  5. 投稿後の反応を見て次へつなげる

人間が毎日これを全部やると、「何を書こう」で止まる。

そこで、作業を

掘る → 書く → 選ぶ → 公開する

に分解した。

過去ログを掘る役、文章にする役、候補を絞る役、投稿する役。

役名まで付け始めると若干ふざけて見えるが、分業そのものには意味がある。

どこか一つが壊れても、全部を止めなくていいからだ。

文章生成がおかしければ公開だけ止める。 投稿経路が止まってもネタ集めは続ける。 候補が弱ければ、その日は出さない。

AIを一匹の万能生物にするより、役割を小さく分けた方が故障箇所が分かりやすい。

もちろん、タヌキは普通に間違える

ここで「AIが全部やってくれて最高でした」で終われば、いかにもAIブログっぽい。

現実はもう少し雑である。

今日、Xの投稿案を作ってもらった。

私は画面を見て言った。

ワイ

Xのコミュニティは英語やで？ブログの記事の中身は確認できるの？

ChatGPT

せやった、コミュニティは英語や。そこは私のミス。X案は英語前提で出し直す。

営業自動化システム、投稿先の言語を人間に指摘される。

この一件だけでも、「全部自動にする」より「最後の判断を人間に残す」方がいい理由が分かる。

AIは速い。

候補を何本も作れる。 過去ログも掘れる。 文章も整えられる。

しかし、今その場で見えている文脈を一発で外すこともある。

だから現在の設計では、公開前に一度止まる。

AIが準備を終えたあと、人間に聞く。

「これ出してええ？」

人間の仕事をゼロにはしない。

人間の仕事を、最後の判断だけにする。

これが今のところ一番しっくりきている。

ところが「判断だけ残す」にも罠があった

ブログ側でも似たことが起きた。

AIが記事候補を選び、

「今日の本命はこれです」

とタイトルと要約を出してきた。

私は言った。

ワイ

せやからブログへの投稿原稿が見られへんと、、、Tanuki Browserはもっと賢くなるんか？

ChatGPT

せやねん。「これ出してええ？」の前に、ブログ本文そのものがここで読めなあかん。タイトルと要約だけ出されても判断できへん。

その通りである。

いや、最初からそうしてくれ。

ここで一つ設計を直した。

人間に「判断だけ」を残すなら、判断材料までAI側で揃えなければ意味がない。

「承認してください」と言われて、そこから本人がファイルを探し、本文を開き、安全性を確認するなら、それは判断だけではない。

準備作業が人間へ戻ってきている。

そこでブログは、

候補を選ぶ → 本文を作る → 公開してよい情報だけか確認する → 本文をそのまま人間に見せる → 「これ出してええ？」

までを一続きにした。

さらに問題があった。正しいけど、おもんない

そして出来上がった記事を読んだ。

内容は正しい。 構成も正しい。 役にも立つ。

でも、何か違う。

また私は言った。

ワイ

内容的には素晴らしいと思うねん。でもな、読み物として楽しいかどうかは別やねん。

ChatGPT

そう、それや。今のC案は「内容は正しい・役に立つ」けど、説明記事に寄りすぎてる。

ここでBlog Factoryをもう一度作り直すことになった。

今度は、記事を書く前に実際の会話のSceneを探す。

単なる名言ではない。

人間が何か変なことを言う。 ChatGPTがツッコむ。 その直後、本当に何かが作られたり、方針が変わったりする。

そういう場面を優先する。

FX大学の記録がおもしろかったのも、結局ここだった。

出来事を後から綺麗に説明したからではない。

当時の人間とAIが、その場で本気でやり取りしているログが残っていた。

真似するなら、最小構成はこれでいい

ここからは真面目な話。

同じように「発信は必要だけど毎日SNSに張り付きたくない」という人なら、大きなAIエージェントを作らなくてもいい。

最初は5つで十分だと思う。

  1. 日々の出来事をログとして残す
  2. AIに公開可能な出来事だけを拾わせる
  3. 実際の会話や失敗があるSceneを優先する
  4. 投稿案を数本作り、人間が一つ選ぶ
  5. 公開済みの記録を残して二重投稿を防ぐ

ポイントは、生成量を増やすことではない。

AIを使えば文章はいくらでも作れる。

だからむしろ大事になるのは、何を出さないかだ。

弱いネタは捨てる。 根拠のない成功談は作らない。 プライベートな話は候補から落とす。 内部事情だけで他人に意味がないものも出さない。

そのうえで、残った実話をちゃんと読み物にする。

AI時代のコンテンツ作りは、「大量生成」より「編集」の方が重要になる気がしている。

結局、人間は何をするのか

最初は、自分がXに張り付かなくて済むようにしたかっただけだった。

それが、

ログを掘るAIができ、 文章を書くAIができ、 候補を選ぶAIができ、 投稿するAIができ、 今度はブログから面白い実ログを探すAIまで増えた。

営業から逃げようとした結果、営業部ができた。

しかも部員はだいたいタヌキである。

ただ、一つだけ人間側に残した仕事がある。

「それ、ほんまに出してええんか？」

を決めること。

営業が苦手なら、営業を好きになる必要はない。

営業するタヌキを作ればいい。

ただしタヌキは、ときどき英語コミュニティへ日本語を持っていこうとする。

最後に一人、人間を置いておいた方がいい。
